# 개발 조사: 플랫폼 제약, 작업량, 팀 구성

> 작성일: 2026-11-10
> 관련 문서: [기획안_v1.md](./기획안_v1.md), [경쟁서비스_조사.md](./경쟁서비스_조사.md), [개발_창업_준비.md](./개발_창업_준비.md)
> 목적: 이번 대회만이 아니라 **다른 대회와 실제 창업까지** 이어간다는 전제로, 개발 범위와 난이도를 확인하고 **개발자 1명 추가가 필요한지** 판단합니다.

## 1. 결론 요약

| 질문 | 답 |
|---|---|
| 이번 대회(11/15 서류, 11/20 발표)에 개발자가 더 필요한가? | **아니요.** 데모는 1명이 1~2주면 만들 수 있는 범위입니다. 지금 새 사람을 받으면 적응 시간 때문에 오히려 느려집니다. |
| 실제 서비스(파일럿)까지 가려면? | 개발 작업량이 **약 10주(전업 1명 기준)**입니다. 학업과 병행해 주 20시간이면 **약 5개월**, 개발자가 2명이면 **약 3개월**입니다. |
| 그럼 1명 더 필요한가? | **대회 이후, MVP를 시작하기 전(12~1월)에 합류시키는 것을 추천합니다.** 다만 일반 개발자보다는 **AI 품질(프롬프트, 평가)을 맡을 사람**이 더 효과적입니다. 이유는 4장에 있습니다. |
| 가장 큰 기술 리스크는? | 코드의 양이 아니라 **(1) Slack 플랫폼 제약**과 **(2) B(오해 탐지)의 정확도**입니다. |

## 2. Slack 플랫폼 제약 (공식 문서·보도로 확인)

이전 문서에서 ⚠️로 표시했던 항목을 확인했습니다. **기획 수정이 필요한 내용이 있습니다.**

### 2.1 확인 결과

| 제약 | 내용 | 영향받는 기능 | 확인 수준 |
|---|---|---|---|
| **스레드 읽기 제한** | 2025년 5월 29일 이후 만든 앱 중 **Slack 마켓에 등록되지 않고 외부에 배포하는 앱**은 스레드·채널 기록을 읽는 API(`conversations.replies`, `conversations.history`)를 **1분에 1번, 한 번에 15개 메시지**까지만 호출할 수 있습니다. 기존 설치에도 2026년 3월 3일부터 적용되었습니다. **마켓 등록 앱과 고객사가 직접 만든 사내 앱은 영향이 없습니다** (사내 앱은 분당 50회 이상, 한 번에 최대 1,000개). | **B(오해 탐지)**, C, G | 🟢 Slack 공식 변경 공지 |
| **데이터 저장·AI 학습 금지** | Slack API로 받은 데이터를 대량으로 내보내거나, **영구 사본·색인·장기 저장소를 만들거나, AI 모델 학습에 쓰는 것**이 금지되었습니다 (2025년 API 약관 개정). AI 학습 금지는 2024년 12월 개발자 정책에도 명시되어 있습니다. | **G(오해 지도)**, 평가 데이터 수집 | 🟢 개발자 정책 / 🟡 법률사무소·언론 해설 (약관 원문은 직접 확인 필요) |
| **보내기 전에 끼어들 수 없음** | 사용자가 Slack 입력창에 쓰는 메시지를 앱이 보내기 전에 가로채는 기능은 없습니다. 이벤트는 메시지를 보낸 **뒤에만** 받을 수 있습니다. | **A(보내기 전 점검)** | 🟡 공식 문서에서 해당 기능을 찾지 못함 (없다는 것을 직접 확인한 문서는 없음) |
| **마켓 심사** | 앱 엔드포인트 보안, 요청 권한(scope)이 꼭 필요한지 검토합니다. **넓은 권한을 요청하는 AI 앱은 더 엄격하게 심사**합니다. 승인 뒤에는 권한이나 설정을 바꿀 때마다 다시 심사받아야 합니다. 공식 소요 기간은 없고, 업체 경험담으로는 2주~3개월입니다. | 정식 출시 전체 | 🟢 Slack 블로그 / 🟡 기간은 업체 경험담 |

### 2.2 새로 찾은 기회

| 기능 | 내용 | 활용 |
|---|---|---|
| **Agents & AI Apps** | 앱 설정에서 켜면 Slack 상단 바와 **화면 옆 분할 창**에서 AI 앱을 쓸 수 있습니다. Bolt에 전용 도구(Assistant 클래스)가 있습니다. | **A를 분할 창에서**: 초안을 분할 창에 쓰면 점검 결과를 보여주고, 사용자가 확인한 뒤 채널에 올리는 흐름. 모달보다 자연스러움 |
| **실시간 검색 API (RTS)** | 2026년 2월 정식 출시. 앱이 데이터를 **저장하지 않고** Slack 안을 검색할 수 있습니다. 마켓 등록 앱과 사내 앱만 쓸 수 있습니다. | 팀 용어나 이전 결정을 찾을 때 저장 없이 맥락 확보 |

### 2.3 기획에 반영할 것

1. **A의 사용 흐름 변경:** "긴 메시지면 자동으로"는 불가능합니다. → **분할 창(Agents & AI Apps)이나 슬래시 명령어로 초안을 쓰는 방식**으로 바꿉니다. 사용자가 일부러 열어야 하므로, "언제 열고 싶어지는가"를 설계해야 합니다.
2. **B는 당분간 버튼으로 실행하는 방식:** 스레드 종료 자동 감지는 계속 읽어야 해서 호출 제한에 걸립니다. → 처음에는 **"이 스레드 점검" 버튼(메시지 단축키)**으로 사용자가 실행합니다. 마켓 등록 전에도 15개 이하 스레드는 1번 호출로 처리할 수 있어 파일럿은 가능합니다. 긴 스레드는 몇 분이 걸립니다.
3. **"데이터가 쌓이는 경쟁 우위"(G) 표현 수정:** Slack 메시지를 저장하거나 학습에 쓸 수 없습니다. → 쌓이는 것은 **우리 앱에서 생긴 데이터**로 한정합니다: 프로필, "더 쉽게/더 자세히" 피드백, B의 확인 질문 답변, 오해 유형 통계. 이것도 Slack 데이터에서 파생된 것으로 볼 수 있으므로 약관 원문 확인이 필요합니다.
4. **처리 후 바로 폐기하는 구조:** 메시지 원문은 처리 후 저장하지 않는 것을 기본 설계로 합니다. 보안 검토와 마켓 심사에도 유리합니다.
5. **마켓 등록이 사업의 관문:** B를 제대로 쓰려면 마켓 등록이 사실상 필수입니다. 심사가 몇 달 걸릴 수 있으므로 **파일럿과 동시에 심사를 준비**해야 합니다.

## 3. 개발 작업량 추정

> 기준: **전업 개발자 1명, AI 코딩 도구 사용** 기준 주 단위. 학업과 병행(주 20시간)하면 약 2배.
> 대략적인 추정이며, 처음 만들어 보는 부분은 더 걸릴 수 있습니다.

### 3.1 대회 데모 (~11/20)
| 작업 | 기간 | 비고 |
|---|---|---|
| Slack 앱 생성, Bolt 설정, 메시지 단축키 | 0.5주 | 우리 워크스페이스의 사내 앱 → 호출 제한 없음 |
| 기본 번역 (프로필 3명은 미리 입력) | 0.5주 | 프롬프트와 직무별 출력 형식이 핵심 |
| B 오해 탐지 (미리 준비한 스레드) | 0.5~1주 | 사람별 요약 → 비교 → 표시까지. 확인 질문 DM은 화면 시안으로 대체 가능 |
| A 보내기 전 점검 (모달 또는 분할 창) | 0.5주 | 우선순위가 낮으면 생략 |
| **합계** | **약 2주** | 서류(11/15)에는 화면 시안이나 녹화 영상으로 대응하고, 발표(11/20)까지 완성 |

### 3.2 MVP + 파일럿 (외부 팀 3~5곳이 실제로 사용)
| 작업 | 기간 | 비고 |
|---|---|---|
| 여러 회사 설치(OAuth), DB, 토큰 암호화 | 1주 | |
| 프로필 설정 화면 (App Home, 모달) | 1주 | 30초 안에 끝나는 설정 |
| 기본 번역 완성 (원문 보기, 추측 표시, 피드백 버튼) | 1주 | |
| A 완성 (분할 창 흐름) | 1주 | |
| **B 완성** (사람별 요약, 비교, 객관식 확인 DM, 결과 취합) | **2~3주** | 가장 복잡하고, 가장 중요함 |
| **평가 체계** (테스트 데이터셋, 자동 채점, 프롬프트 비교) | **2주 + 계속** | Slack 데이터를 쓸 수 없어서 인터뷰 사례와 직접 만든 시나리오로 구축 |
| 배포, 모니터링, 개인정보 가리기, 로그 관리 | 1주 | |
| **합계** | **약 9~10주** | 주 20시간 1명 → **약 5개월** / 2명 → **약 3개월** |

### 3.3 정식 출시
| 작업 | 기간 | 비고 |
|---|---|---|
| 마켓 심사 대응 (권한 축소, 보안, 문서) | 2~4주 + 대기 | 대기 기간이 2주~3개월로 불확실 |
| 결제 연동 | 1~2주 | |
| D 언어 동시 번역 | 1주 | 프로필에 언어만 추가 |
| 관리자 웹 대시보드 (팀 설정, G 통계) | 3~4주 | **여기서 처음으로 웹 프론트엔드가 필요함** |
| 보안 질의서 대응, 데이터 처리 문서 | 1~2주 | |
| (선택) 두 번째 플랫폼 (Teams, 잔디 등) | 플랫폼당 4~8주 | 시장 결정에 따라 |
| **합계** | **약 9~13주 + 심사 대기** | |

### 3.4 기술 구성 (추천)
| 영역 | 선택 | 이유 |
|---|---|---|
| 언어 | Python | AI 관련 자료와 도구가 가장 많음. Slack Bolt 공식 지원 |
| Slack | Bolt for Python + Agents & AI Apps | 분할 창, 3초 규칙 대응, 서명 검증 기본 제공 |
| AI | 범용 AI API (Claude 등) | 직접 학습할 필요 없음. 작은 모델로 시작하고 B만 큰 모델 |
| DB | PostgreSQL (Supabase 등 관리형) | 프로필, 팀, 피드백, 토큰만 저장 |
| 배포 | Cloud Run, Fly.io 등 | 서버 관리 최소화 |
| 웹 (나중에) | Next.js | 관리자 대시보드가 필요해질 때만 |

> **UI는 Slack이 정한 틀(Block Kit) 안에서 만듭니다.** 초기에는 웹 프론트엔드가 필요 없고, 디자이너는 Block Kit Builder로 화면 시안을 직접 만들 수 있습니다.

## 4. 팀 구성 판단

### 4.1 개발 업무를 성격별로 나누면

| 영역 | 비중(MVP 기준) | 성격 | 지금 누가? |
|---|---|---|---|
| Slack 앱 + 백엔드 | 약 40% | 정해진 방법이 있어 AI 코딩 도구로 빨라지는 영역 | 나 |
| **AI 품질** (프롬프트, 평가 데이터, 정확도 개선) | **약 40%** | 정답이 없고 실험을 반복해야 함. **도구로 빨라지지 않는 영역** | 나 (겸임) |
| 인프라·보안·개인정보 | 약 20% | 체크리스트 기반 | 나 |
| 화면 설계 (Block Kit), 랜딩 페이지 | - | 디자인 | 팀원 |

**핵심:** 코드 작성은 AI 도구 덕분에 1명이 많이 해낼 수 있지만, **B의 정확도를 끌어올리는 일**은 데이터를 만들고, 채점하고, 고치는 반복이 필요해서 시간이 줄지 않습니다. 그리고 이 부분이 **우리 서비스의 차별점 그 자체**입니다. 그래서 개발자를 더 뽑는다면, 이 부분을 맡을 사람이 가장 효과적입니다.

### 4.2 1명을 더 뽑아야 하는 이유와 뽑지 않아도 되는 이유

| 추가해야 하는 이유 | 지금은 안 해도 되는 이유 |
|---|---|
| 혼자 하면 MVP까지 약 5개월. 2명이면 약 3개월 | 대회 데모는 혼자 충분히 가능 |
| AI 품질과 앱 개발을 동시에 진행할 수 있음 | 문제 검증(인터뷰) 전에 개발을 키우면 방향이 틀렸을 때 낭비가 큼 |
| **개발자가 1명뿐이면 그 사람이 빠지면 프로젝트가 멈춤** | 사람이 늘면 지분, 역할, 의사결정 비용이 생김 |
| 창업 지원사업과 투자 심사에서 **팀 구성(기술 역량)**을 평가함 | 맞지 않는 사람을 받으면 나중에 정리하기 어려움 |
| 대회를 여러 개 병행할 때 일정 여유 | |

### 4.3 추천

1. **이번 대회:** 지금 팀 그대로 진행합니다.
2. **대회 직후 ~ 12월:** 인터뷰로 문제 검증을 먼저 진행합니다. 기획+디자인 팀원이 주도하면 좋습니다.
3. **12~1월 (MVP 시작 전):** 검증 결과가 긍정적이면 개발자 1명을 추가합니다.
   - **우선순위 1: AI/데이터 쪽 역량** (프롬프트 설계, 평가 데이터셋, 실험 경험)
   - **우선순위 2: 백엔드·인프라** (내가 AI 쪽에 더 강하다면 이쪽)
   - 프론트엔드 전문 인력은 관리자 대시보드가 필요한 출시 단계 전까지는 필요 없음
4. **바로 공동창업자로 받지 않기:** 2~4주짜리 작은 과제(예: B 평가 데이터셋 구축과 정확도 측정)를 함께 해보고 결정합니다. 지분과 역할은 그 뒤에 정리합니다.

### 4.4 판단 체크리스트 (팀원과 함께 확인)

- [ ] 나는 학기 중에 이 프로젝트에 주 몇 시간을 쓸 수 있는가? (15시간 미만이면 추가 필요성이 커짐)
- [ ] 나의 주력은 앱·백엔드인가, AI·데이터인가? (빈 쪽을 채울 사람을 찾음)
- [ ] 목표 일정이 있는가? (예: 내년 상반기 창업 지원사업 신청 → 그 전에 파일럿 결과 필요)
- [ ] 다음에 나갈 대회나 지원사업이 팀 구성을 평가하는가?
- [ ] 새 사람에게 줄 수 있는 것은 무엇인가? (지분, 역할, 경력, 대회 상금 배분)
- [ ] 후보가 2~4주 시험 과제를 함께할 의향이 있는가?

## 5. 지금 할 일

1. **기획안 수정:** 2.3의 다섯 가지(A 흐름, B 실행 방식, G 표현, 저장하지 않는 구조, 마켓 등록 일정)를 반영합니다.
2. **데모 범위 확정:** 기본 번역 + B를 우선 만들고, A는 시간이 남으면 진행합니다.
3. **Slack 약관 원문 확인:** API 약관과 개발자 정책 원문에서 "파생 데이터 저장"이 허용되는지 확인합니다. G 기능과 경쟁 우위 논리에 직접 영향을 줍니다.
4. **팀원과 4.4 체크리스트로 논의**합니다.
