# Sairo — Lightweight User Validation Protocol

This is a development test scenario and recording template, not evidence that sessions have occurred. Do not aggregate or publish results until actual sessions are run with consent.

## Session setup

- Recruit one participant at a time; record their self-described role, not identifying details.
- Explain that the prototype uses prepared examples and simulated answers, has no live AI, and stores no session after refresh.
- Ask permission before recording notes. Do not paste real company messages into the demo.
- Start a timer when the participant begins each task. Stop when they state they are done or ask for help.

## Tasks and questions

| Scenario ID | Test question | Prompt |
|---|---|---|
| purpose-01 | Does the user understand Sairo’s purpose? | “In your own words, what is this tool helping the team do?” |
| translation-01 | Can the user compare source and rewrite? | “What changed between the original message and Jamie’s version? Did the rewrite add or remove a commitment?” |
| evidence-01 | Can the user distinguish an estimate from a fact? | “What does ‘Potential misunderstanding’ mean here? Which messages support it?” |
| response-01 | Does the user know what to do next? | “What would you do after seeing this candidate? What do the three response states mean?” |
| criteria-01 | Does the flow clarify completion criteria? | “After using Before sending, what is still unspecified about ‘done by Friday’?” |

## Record one row per task

| Scenario ID | Participant role | Success (yes / partial / no) | Completion time | Misunderstood content (verbatim note) | Uncomfortable screen | Suggested change |
|---|---|---|---|---|---|---|

Record observations without inferring intent. Use “not observed” when a field is unavailable. Report counts only after sessions are actually completed, with the number of participants and method stated. Do not create sample answers, success rates, or completion-time statistics in advance.
